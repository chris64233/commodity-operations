# commodity-operations

用于管理大宗商品合同、库存批次、物流作业与结算资料的后端服务。

## 开发环境

- JDK 21
- Spring Boot 4.1.1
- Maven Wrapper 3.9.9
- H2

## 常用命令

运行测试：

    ./mvnw clean test

启动服务：

    ./mvnw spring-boot:run

## 分批交货与数量容差控制

### 合同

登记合同时需指定商品、基础数量、短装比例、溢装比例、交货期限和计量单位。
系统据此计算允许区间：

- 最低可接受数量 = 基础数量 × (1 - 短装比例)
- 最高可接受数量 = 基础数量 × (1 + 溢装比例)

### 交货登记

- 每笔交货携带外部单号、商品、单位、实际数量和交货时间；商品或单位与合同不一致会被拒绝。
- 累计交货数量（交货减冲销）不得超过最高可接受数量，超出部分入账失败。
- 并发登记通过对合同行加悲观写锁串行化，只有仍在可接收余量内的交货能成功。
- 幂等：同一合同下外部单号唯一。相同单号且内容完全一致的重放返回原记录；
  单号相同但商品、单位、数量或交货时间任一不同则返回 409 冲突。

### 合同关闭

- 累计数量达到最低可接受数量后才允许关闭；已关闭合同的重复关闭请求幂等返回原关闭记录。
- 关闭与新交货并发时由行锁保证只有一个先成功：关闭先生效则迟到交货被拒绝（409）；
  交货先入账则关闭按新的累计数量重新判断是否达到下限。

### 冲销

- 已入账的错误交货只能追加冲销记录（数量为负、关联原交货），原记录保留不可删除；
  每笔交货最多被冲销一次，冲销同样支持按外部单号幂等重放。
- 冲销后若累计数量跌破最低可接受数量且合同已关闭，合同转为 `PENDING_REVIEW`（待复核），
  原关闭记录保留并标记为 `REOPENED`，不会假装合同从未关闭。

### 合同状态机

```
OPEN --(累计 ≥ 最低可接受数量, 申请关闭)--> CLOSED
CLOSED --(冲销导致累计 < 最低可接受数量)--> PENDING_REVIEW
```

- `OPEN`：接收交货，可申请关闭。
- `CLOSED`：不再接收交货；重复关闭幂等返回原关闭记录。
- `PENDING_REVIEW`：不接收交货、不允许关闭，等待人工复核。

### 接口

- `POST /api/contracts` 登记合同
- `POST /api/contracts/{id}/deliveries` 登记交货
- `POST /api/contracts/{id}/deliveries/{deliveryId}/reversals` 追加冲销
- `POST /api/contracts/{id}/close` 申请关闭
- `GET /api/contracts/{id}` 查询合同概要：基础数量、容差区间、累计交货、
  可继续接收数量、交货与冲销明细、关闭历史
