# commodity-operations

用于管理大宗商品合同、库存批次、物流作业与结算资料的后端服务。

## 开发环境

- JDK 21
- Spring Boot 4.1.1
- Maven Wrapper 3.9.9
- H2

## 常用命令

运行测试：

    ./mvnw clean test

启动服务：

    ./mvnw spring-boot:run

## 散货船装卸时间与滞期费结算

模块包：`com.chris64233.commodityoperations.laytime`

### 时间计算口径

- **起算与终止**：装卸时间自 `START`（开工）事件发生时刻起算，至 `COMPLETE`（完工）事件发生时刻终止。
  `BERTH`（靠泊）是必要前置事件，但靠泊后、开工前的等待时间不计入装卸时间。
- **停算扣除**：默认规则 `DEDUCT_PAUSE_INTERVALS` 下，每个 `PAUSE`（暂停）与 `RESUME`（复工）
  按发生时间 FIFO 配对形成停算区间；停算区间从有效占用时间中扣除。多个暂停区间相互重叠或嵌套时
  按**并集合并，只扣除一次**。
- **连续计算规则**：合同登记为 `CONTINUOUS` 时，任何暂停都不扣除（暂停事件仍需满足时间线完整性）。
- **计量单位**：内部统一按**秒**存储与计算；滞期费按秒占费率/小时等比折算
  （`超出秒数 × 每小时费率 ÷ 3600`），金额保留 2 位小数，四舍五入；未超出允许装卸时间时滞期费为 0。
- **排序规则**：事件按发生时间升序重建时间线，与接收先后无关（支持晚到、乱序事件）；
  同一时刻按 靠泊 → 开工 → 暂停 → 复工 → 完工 定序。

### 事件登记与幂等

每个事件保留外部事件号、发生时间（业务时间）和系统接收时间（以首次接收为准）。

- 同外部事件号、同类型、同发生时间的重放为幂等操作，不改变任何结果（返回 `replayed=true`）。
- 同外部事件号但类型或发生时间不同，返回 `409 EVENT_CONFLICT`。
- 每接受一个新事件，航次的事件版本号 +1。

### 时间线校验（拒绝结算的情形）

缺少靠泊/开工/完工任一必要事件、同类锚点事件出现多个、开工早于靠泊、完工早于开工、
复工没有对应暂停、暂停到完工仍未复工、暂停/复工落在开工之前或完工之后等无法解释的时间线，
返回 `422 UNPROCESSABLE_TIMELINE` 并指出具体问题，且不会产生任何结算单。

### 结算版本与差额调整

- 结算单生成时固定当时的合同规则（允许装卸时间、费率、币种、停算规则）与事件版本号，
  并快照规范化时间线、停算区间和纳入的事件号。
- 结算确认后，迟到事件**不能覆盖**原结算；再次计算必须提供调整原因，系统生成新版本
  （`basedOnSettlementId` 指向前一版本），原版本的金额、状态和调整原因永久保留。
- 新版本记录逐项差额来源：事件版本、停算扣除时长、已用时间、超出时间、滞期费金额的旧值/新值/差额。
- 只有**基于最新完整事件版本的当前草稿**才能确认；重算与确认并发时，通过航次级悲观锁串行化，
  落后版本的确认返回 `409 SETTLEMENT_CONFLICT`。计算失败时事务回滚，不会产生半张结算单，
  已确认金额永不改变。

### HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/laytime/voyages` | 登记航次合同（允许装卸时间用 ISO-8601 时长，如 `PT72H`） |
| POST | `/api/laytime/voyages/{voyageNo}/events` | 登记作业事件（幂等/冲突） |
| POST | `/api/laytime/voyages/{voyageNo}/settlements` | 生成/重算结算（已确认后重算 body 需带 `reason`） |
| POST | `/api/laytime/voyages/{voyageNo}/settlements/confirm` | 确认当前草稿结算 |
| GET | `/api/laytime/voyages/{voyageNo}` | 原始事件、规范化时间线、停算区间、各版结算与差额来源 |
